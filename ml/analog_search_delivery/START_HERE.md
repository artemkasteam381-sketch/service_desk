# Только поиск аналогов: с чего начать

Рабочие варианты: BM25, BGE-M3 и их сочетание по рангам (RRF, k=60, по 100 групп от каждого метода). Вход — только текст. Классификатор пока не участвует.

## 1. Оцените полезность

Откройте `analog_review/review.html` обычным браузером. Страница работает локально, без сервера и внешних запросов. Если просматриваете файлы исходного проекта, она находится в `outputs/analog_review/review.html`.

На странице 384 пары для 40 validation-запросов. Это объединение топ-5 всех трёх методов. Выбирайте:

- 0 — другая проблема или бесполезный результат;
- 1 — похожий контекст/симптом, но мало практической пользы;
- 2 — полезный аналог для диагностики или следующего шага.

Оценивается группа: при необходимости раскройте другие записи. Пустое решение не означает автоматически нулевую полезность. Названия поисковых методов и позиции скрыты. Истинная категория нового запроса тоже скрыта. Причина оценки помогает обсуждать спорные примеры с командой.

Периодически нажимайте «Скачать judgments.csv»: автосохранение зависит от разрешений браузера. Сохраните скачанный файл отдельно, например `judgments_reviewed.csv`. Затем укажите его в notebook и пересчитайте метрики. Не заменяйте непроверенные пары оценкой 0. Рекомендуется часть примеров независимо оценить двум участникам.

Для трёх запросов очищенное ядро пустое: выдача пустая и качество учитывается как ноль. Их нельзя молча исключать. Всего история эксперимента содержит 899 непустых записей; группы validation/test/calibration исключены целиком. При рабочем поиске доступна полная история, но пустые тексты в выдачу не попадают.

## 2. Попробуйте новый текст

Используйте `analog_search.ipynb`: он отдельно загружает модель, а затем позволяет менять текст без повторной загрузки. По умолчанию загрузка модели выключена, чтобы просмотр результатов не занимал память; установите `LOAD_BGE = True` для семантического поиска.

Либо из каталога, содержащего `support_search`:

```bash
python -m support_search.focused \
  --source /Users/memchik/Downloads/pochtatech_notebook \
  --query 'Не приходит СМС с кодом входа в приложение' \
  --method hybrid --out example_new.json
```

Для быстрого лексического поиска замените `hybrid` на `bm25`. Для чистого семантического — на `bge`. Новый путь вывода должен быть свободен, чтобы не затереть результаты. Зависимости: `support_search/requirements.txt`.

Источники — текущие `results/appeals_parsed.csv`, `embedding_manifest.json`, `embeddings_*.npz` и локальная модель в `model_cache` из большого notebook. Они не включены в архив. В notebook поменяйте `SOURCE`, если переместили эту папку. Кэш проверяется по текстам, порядку строк, модели и revision. При новых данных нужно сначала пересобрать кэш; молча применять старые векторы к новым строкам нельзя.

Для воспроизведения именно текущего сравнения используется `text_core`, а не `text_with_subject`. Добавление темы и смена парсера — отдельный будущий эксперимент с пересчётом векторов. Известные нечёткие группы дубликатов унаследованы от старого notebook и требуют ручного аудита.

## 3. Передайте интерфейс участнику, который делает сайт

```python
engine = AnalogSearch(records, history_vectors, encoder)
response = engine.search(raw_text, method="hybrid")
```

Создавайте `engine` и `encoder` один раз при старте. `response['results']` содержит до пяти разных групп. Поля: `id`, `original_text`, `topic`, `support_line`, `result`, `source_url`, `duplicate_variants`, `category_conflict`. Если ссылки нет — показывайте ID. Если `result` пуст — «Решение в истории не указано». Значение «Решение предоставлено» — исторический статус, не подробная инструкция.

`ranking_score` не является вероятностью, не показывайте его как процент уверенности. Топ-5 не гарантирует, что в истории вообще есть полезный аналог. В этой версии нет обученного порога отказа по релевантности. Для проверки новых запросов вне истории модель обязательна; кэш проверочных запросов используется только в подготовленном эксперименте.

## 4. Что измерено и что пока неизвестно

- Выполнены три метода на 40 одинаковых запросах; подготовлены 384 уникальные пары, без выдуманных ручных меток.
- Реально выполнен BGE-M3 на новом тексте. Проверена совместимость живого encoder с кэшем: cosine 1,0 на контрольном тексте.
- На пяти коротких новых запросах с загруженной моделью, CPU / два потока: медиана BM25 около 1,1 мс, BGE 57,8 мс, гибрид 54,8 мс. Разницу BGE и гибрида на такой маленькой выборке нельзя интерпретировать как преимущество гибрида по скорости. Пик RSS общего процесса примерно 1,73 GiB.
- В отдельном холодном запуске загрузка модели заняла 9,2 с, первый запрос — 10,9 с. Модель следует держать загруженной и прогреть до демонстрации.
- `analog_benchmark.json` содержит измерения с вычислением нового эмбеддинга. Задержки в `analog_review/metrics.json` относятся **только к поиску с готовым вектором** и не являются задержкой сервиса.
- Это короткая проверка работоспособности на текущем компьютере, не нагрузочный тест. Память общая для методов, включает модель и индекс. CUDA/MPS в этом запуске не измерялись.
- 18 автоматических тестов пройдены. Страница разметки проверена на синтаксис JavaScript; визуальная проверка во встроенном браузере заблокирована его политикой локальных файлов.
- Полезность ещё не размечена: нельзя выбрать победителя по реальному качеству. Validation уже использовался раньше; для финального доказательства нужен отдельный заранее зафиксированный test.

После заполнения меток сравните `useful_at_5`, `pool_ndcg_at_5`, `precision_at_5` и парную разницу. nDCG относительно общего пула не измеряет полноту по всей истории. Выбирайте базовый метод на validation; classifier и reranker добавляйте по одному, только после этого выбора.
