# Методология аналитики обработки обращений

## 1. Источник данных

Источник:

`data/raw/original.xlsx`

Единица анализа:

Одно обращение = одна строка датасета.

Всего обращений:

1931.

---

# 2. Определение просрочки SLA

## Источник истины

Для определения факта нарушения SLA используется поле:

`Просрочен?*`

Значения:

- `Просрочен`
- `Не просрочен`

Причина использования:

В данных присутствуют поля нормативного и фактического времени обработки, однако простое сравнение:
Фактическая длительность SLA > Нормативное время SLA

не полностью повторяет историческую бизнес-логику.

Проверка показала:

- совпадений с исторической меткой: 1926;
- расхождений: 5.

Поэтому историческая отметка принимается как основной источник.

---

# 3. Расчёт доли просрочек

Используется показатель:
Доля просрочки =
Количество обращений со статусом "Просрочен"
/
Все обращения категории
× 100%


Применяется для анализа:

- услуг;
- видов обращений;
- приоритетов;
- линий поддержки.

---

# 4. Длительность обработки

Для анализа сроков используется поле:

`Фактическая длительность выполнения запроса (SLA)`

Рассчитываются:

- среднее время обработки;
- медианное время обработки;
- максимальное время обработки.

Медиана используется дополнительно, так как среднее значение может искажаться обращениями с очень большим временем обработки.

---

# 5. Анализ нагрузки

Нагрузка определяется количеством обращений.

Используются группировки:

- по услуге;
- по виду запроса;
- по приоритету.

Показатель:
Количество обращений категории

отражает объём входящего потока.

---

# 6. Определение участия линий поддержки

В данных отсутствует полный журнал маршрутизации обращения между линиями.

Поэтому используется приближение:

Если поле: Суммарное время работы N линии

больше 00:00:00,

то считается, что линия участвовала в обработке обращения.

Рассчитывается:
Количество участвовавших линий =
количество линий с ненулевым временем работы

Ограничение:

Показатель отражает наличие работы линии, но не гарантирует фактическую последовательность передачи обращения.

---

# 7. Анализ нескольких линий

Обращение считается обработанным несколькими линиями, если:
Количество участвовавших линий >= 2

Показатель используется для выявления сложных обращений.

---

# 8. Анализ уточнений

Используются поля:

- `Количество уточнений`
- `Суммарное время уточнений`

Рассчитываются:

- доля обращений с уточнениями;
- количество обращений с 2+ уточнениями;
- связь количества уточнений с длительностью обработки.

---

# 9. Исторический риск SLA

Прогнозная модель не используется.

Риск рассчитывается на основе истории:
Риск SLA =
Просроченные обращения категории
/
Все обращения категории
× 100%

Используется для поиска категорий с повышенной исторической долей нарушений.

Анализ проводится для:

- услуг;
- видов обращений;
- линий поддержки.

---

# 10. Ограничения аналитики

1. История переходов между линиями поддержки отсутствует.
   
   Используется приближение через время работы линий.

2. Исторический риск SLA показывает прошлую частоту нарушений, но не является прогнозом будущих нарушений.

3. Расчёт SLA через разницу времени не используется как основной показатель, так как не учитывает все правила обработки обращений.
