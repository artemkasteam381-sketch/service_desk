# Линия поддержки и похожие обращения: единая предобработка

Сборка заменяет агрессивный парсер присланного сервиса на `essence_first`
из `classification_service_integration/models/classification/inference.py`.
Функции перенесены из ZIP дословно: `normalize`, `extract_essence`,
`essence_first_text`, `group_key`. Нормализация категориальных полей также совпадает:
пустые значения и `---)` преобразуются в `__MISSING__`.

В ZIP классификации есть две разные текстовые ветки:
- TF-IDF — `full_plus_essence`, в том числе отдельный лемматизированный блок;
- нейросеть — `essence_first`: последний непустой фрагмент «Суть обращения»
  переносится в начало, регистр, коды и остальное описание сохраняются.

Для BGE и MiniLM применяется именно нейросетевая ветка **без лемматизации**.
При отсутствии маркера остаётся полный нормализованный текст. Старое удаление
подписей, HTML, полей формы и хвостов переписки больше не применяется.
Изменение парсера требует переобучения LR и пересчёта индекса, а не только замены parser.py.
Прежние оценки 0.671 и поисковые метрики к новым весам не относятся.

## Сборка в Colab

Откройте `support_line_search_rebuild.ipynb`, выберите GPU T4 и выполните ячейки.
Загрузите исходный Excel (лист `Sheet0`) или CSV с разделителем `;`.
Все исходники уже встроены в ноутбук: старые веса и ZIP классификации загружать не нужно.

Скрипт скачает закреплённые версии BGE-M3 и MiniLM, рассчитает признаки,
выполнит трёхфолдовую группированную проверку LR, обучит финальные классификаторы
и сохранит **полные веса обеих нейросетей**, LR, кодировщик, историю, векторы и отчёты.
В конце скачается `support_service_weights.zip`. Ожидайте архив порядка нескольких ГБ:
Google Drive не используется, но локальное место Colab нужно и для моделей, и для ZIP.
В последней ячейке есть повторная ссылка скачивания, если браузер прервал передачу.

Обучается логистическая регрессия; BGE и MiniLM остаются предобученными.
Исходный алгоритм: BGE без E5-префиксов; окна 384 токена с перекрытием 64,
нормированное усреднение векторов окон; 50 разных групп → MiniLM → 5 аналогов.
MiniLM видит первые 128 токенов запроса и окна документа по 350 токенов.
Теперь суть попадает в начало запроса до этого усечения.

В переданных файлах нет исходного обучения LR и весов, поэтому его параметры
восстановить нельзя. Здесь явно задан новый фиксированный вариант:
`C=1, solver=lbfgs, class_weight=None, max_iter=3000, random_state=42`.
Вес каждой группы дубликатов в обучении и групповых метриках равен 1.
TF-IDF или модель 15 категорий не переобучаются и не включаются в итоговый пакет.

## Локальная сборка

Python 3.10+, установленные PyTorch и зависимости:

```bash
pip install -r requirements-build.txt
python train_export.py --source requests.xlsx --output support_service_weights --device cuda
```

Для CPU передайте `--device cpu`; для меньшего потребления VRAM — `--batch-size 4`.
Выходная папка должна быть новой. Зависимости обучающей среды фиксируются в итоговом
`requirements.txt`; чужие версии из macOS-пакета не копируются.

## Запуск полученного ZIP

Распакуйте ZIP, создайте чистую среду и из папки сервиса выполните:

```bash
pip install -r requirements.txt
python app.py
```

Откройте http://127.0.0.1:8765. После установки библиотек и распаковки моделей сеть
для прогнозов не нужна. Экспорт запускает проверку сервиса с отключённой сетью Hugging Face
и пустым кэшем в новом процессе. Если она не проходит, ZIP не помечается готовым.

```python
from app import SupportService
service = SupportService()
answer = service.query('Суть обращения: не загружается список', {'Услуга': 'Личный кабинет'})
print(answer['recommended_line'], answer['scores'], answer['analogs'])
```

API совместим с присланным сервисом: `POST /api/predict`, `GET /api/options`.
Для исторической записи добавлен `GET /api/records/{row_index}`; URL есть в каждом аналоге.
В аналоге также возвращается `category`. `result` и `line` — исторические исходы,
в BGE-векторы и признаки нового обращения они не включаются.

## Проверка и ограничения

Цель — `Кем решен (группа)`, то есть линия решения, а не обязательно первая линия маршрута.
Признаки: описание и только Услуга, Тип запроса, Компонент услуги 1 уровня, Пользователь.
Если все четыре поля отсутствуют, используется отдельно обученная текстовая LR.

`reports/metrics.csv` содержит row/group Accuracy, Weighted-F1, Macro-F1 для всех линий
и отдельно линий 1–3. `fold_metrics.csv`, `oof_*.csv/.npz` и `per_line_*.csv` позволяют
проверить выводы. Группы не пересекаются между train и validation; OneHotEncoder
обучается отдельно внутри каждого fold. Замороженные внешние эмбеддинги допускают
расчёт один раз: они не обучаются на метках этой выборки. Настройки по внешним фолдам
не выбираются. Четвёртая линия имеет один пример в исходном файле: в соответствующем
фолде модель не может научиться этому классу, пропуск отмечается в отчёте.
Финальная модель обучается на всех пригодных строках, включая редкий класс.

`text_audit.csv` показывает исходный и подготовленный текст и возможные маркеры
послерегистрационных исходов. Проверяйте этот отчёт: сохранение полного текста
не гарантирует, что в самом исходном описании нет дописанного ответа поддержки.
Поэтому строки с такими маркерами явно исключаются из обучения и поисковых кандидатов,
но остаются в `records.json` и аудите. Сам текст не обрезается и не переписывается:
функция предобработки совпадает с ZIP, а фильтр допустимости строк — отдельный шаг.
Потерю данных и ложные срабатывания проверьте по `excluded_rows.csv` и `text_audit.csv`.
После восстановления исходных описаний регистрации можно пересобрать модели.
Этот фильтр консервативен и не гарантирует выявление всех утечек без маркеров.

Группировка учитывает нормализованные дубли, URL, email, длинные номера; она не
находит все семантически близкие перефразировки. Это требует отдельного аудита.
Пример, совпадающий с историей, не является тестом обученного классификатора.
Поисковые метрики не выдумываются: после новой обработки нужна новая человеческая
разметка результатов. Оценки LR и MiniLM не объявляются калиброванной уверенностью.

В этой поставке кода локально проверены совпадение предобработки, обучение LR,
изоляция групп и интеграционный API на тестовых адаптерах. Полные нейросети
без переданных весов здесь не запускались; полный прогон выполнит Colab.
