# Подключение категоризации к вашему сервису

В комплекте уже находится финальная модель `catboost_confidence` из запуска
`metadata_results_20260922_023105.zip`: OOF F1 weighted = 0,765104.
Это стекинг TF-IDF + LogisticRegression, замороженной RuBERT с обученной
логрегрессионной головой и CatBoost с 10 признаками уверенности/согласия.
Архив подготовлен для существующего приложения Streamlit. Обучение выполняется
в ноутбуке, а приложение загружает готовый экспорт и вызывает предсказание.

В приложенных вами файлах `app.py` вызывает `src.ui.dispatcher_tab` и
`src.ui.analytics_tab`. Содержимое этих двух модулей не было приложено.
Поэтому комплект добавляет отдельный модуль `src/classification/` и демонстрационную
форму. Существующие файлы репозитория не заменяются.

**1. Разместите комплект в корне репозитория.**

| Путь | Назначение |
|---|---|
| `src/classification/service.py` | загрузка модели и единый метод `predict` |
| `src/classification/ui.py` | форма Streamlit и кеширование модели |
| `src/classification/settings.py` | настройки из переменных среды и `.env` |
| `models/classification/` | финальная модель, точный код признаков и описание экспорта |
| `classification_demo.py` | самостоятельная проверка интерфейса |
| `check_classification.py` | проверка одного прогноза в терминале |
| `requirements-classification.txt` | версии зависимостей модели |
| `tools/export_classifier.py` | импорт следующего запуска ноутбука |
| `notebook_export_cell.py` | код завершающей ячейки ноутбука для будущих запусков |

**2. Установите зависимости в отдельном окружении проекта.**

Экспорт создан в Python 3.13.15; адаптер также проверялся на Python 3.12.
Используйте Python 3.12 или 3.13 и зафиксированные версии ML-пакетов.
Ваш `requirements.txt` оставлен прежним; установите оба файла одной командой:

```bash
python -m venv .venv
```

Активация в Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Активация в Linux/macOS:

```bash
source .venv/bin/activate
```

Затем:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt -r requirements-classification.txt
```

Для CPU на Windows/Linux можно сначала установить CPU-сборку PyTorch:

```bash
python -m pip install torch==2.11.0 --index-url https://download.pytorch.org/whl/cpu
```

После этого выполняется общая команда установки двух requirements. Суффикс `+cpu`
в исходном `requirements_versions.txt` описывает сборку исходной среды; в requirements проекта
оставлена та же версия PyTorch 2.11.0 с возможностью выбрать платформенную сборку.
Для GPU используйте подходящую вашей CUDA сборку той же версии.

**3. Настройте папку модели.**

По умолчанию всё уже настроено на `models/classification` и CPU.
Если нужен другой путь, добавьте строки из `classification.env.example` в ваш `.env`:

```dotenv
CLASSIFICATION_MODEL_DIR=models/classification
CLASSIFICATION_DEVICE=cpu
CLASSIFICATION_BATCH_SIZE=16
```

Относительный путь отсчитывается от корня проекта, а не от рабочей директории терминала.
Настройки `DATA_PATH` и `LLM_ENABLED` на предсказание вида запроса не влияют.

**4. Проверьте модель и форму отдельно.**

```bash
python check_classification.py
python -m streamlit run classification_demo.py
```

При первом прогнозе `transformers` загружает исходную `cointegrated/rubert-tiny2`
с Hugging Face. Её веса не содержатся в `stacking_bundle.joblib`: там находятся
TF-IDF, категориальный encoder, базовые логрегрессии и финальный CatBoost.
Затем RuBERT используется из кеша. Для автономного сервера сначала выполните
проверочный прогноз в среде с интернетом, сохраните кеш Hugging Face и при необходимости
установите `HF_HUB_OFFLINE=1`. Дополнительное обучение RuBERT не выполняется.

Проверка с полной карточкой обращения:

```bash
python check_classification.py --request example_request.json
```

JSON должен содержать `Описание` (или `Описание 2`) и доступные поля регистрации
с точными названиями и исходными значениями. Пример формы принимает те же значения.
Если поля отсутствуют, они передаются как пропущенные; качество на одном тексте
может отличаться от CV, где метаданные были доступны.

**5. Подключите блок к существующему `app.py`.**

Добавьте импорт:

```python
from src.classification.ui import render_classification_panel
```

Внутри существующей вкладки диспетчера добавьте вызов:

```python
with dispatcher_tab:
    render_classification_panel()
    render_dispatcher_tab()
```

Это добавляет самостоятельную форму категоризации и сохраняет текущий блок диспетчера.
Аналитика продолжает вызываться прежним способом. Если в `render_dispatcher_tab()` уже
есть подходящая форма, используйте её поля и вызывайте сервис в её обработчике, чтобы
не дублировать ввод. В `src/classification/ui.py` есть готовый пример кеширования
экземпляра через `st.cache_resource` и показа результата.

Вызов из существующего Python-обработчика:

```python
from src.classification.service import RequestClassifier

# Создать один раз, в Streamlit — через st.cache_resource.
classifier = RequestClassifier('models/classification', device='cpu')

# appeal — словарь исходной карточки обращения.
result = classifier.predict(appeal, current_kind=appeal.get('Вид запроса'))

recommended = result['recommended_kind']
alternatives = result['top3']
comparison = result['comparison']
```

`predict` возвращает обычный словарь, пригодный для JSON. Поля результата:

| Поле | Значение |
|---|---|
| `recommended_kind` | рекомендуемая категория |
| `top3` | три объекта с `label` и числовым `score` |
| `current_kind` | вид, переданный для сравнения |
| `comparison` | `matches`, `differs`, `not_supplied` или `outside_top15` |
| `missing_fields` | отсутствующие поля регистрации |
| `model_variant` | вариант сохранённого стекинга |

Исходный «Вид запроса» никогда не передаётся в признаки. Он сравнивается с результатом
после независимого предсказания. Поля решения, фактических исполнителей и результата
работ также не попадают в модель. Сервис не меняет категорию обращения автоматически.

Если результат — «Вне топ-15», точный вид модель не определяет. Это один агрегированный
класс, а не полный классификатор всех существующих видов. Оценки топ-3 не являются
калиброванной вероятностью правильного ответа.

**6. Какие поля передавать.**

Описание обязательно. Остальные поля берутся из карточки на момент регистрации:

| Поле модели | Комментарий |
|---|---|
| `Описание 2` или `Описание` | полный исходный текст; извлечение сути выполняет runtime |
| `Услуга` | исходное значение системы |
| `Компонент услуги 1 уровня` | исходное значение системы |
| `Тип запроса` | самостоятельное поле, отличается от целевого «Вид запроса» |
| `Пользователь` | тот же формат, что был в обучающем датасете |
| `Критичность`, `Срочность`, `Приоритет` | исходные значения, без новой ручной нумерации |
| `Способ обращения`, `Класс обслуживания` | если доступны |
| `Часовой пояс запроса` | если доступен |
| `Норматив ное время обработки (SLA)` | точное имя из обучающей схемы, включая пробел |
| `Плановое время выполнения`, `Крайний срок обработки` | только значения, заданные при регистрации |

Не заменяйте плановые значения фактическими сроками из обработанного обращения.
Отсутствующие значения можно передавать как `None` или пустую строку.

**7. Как подготовить следующий запуск ноутбука.**

Сохраните текущие настройки текста и признаков. После проверки OOF-метрик выберите
вариант явно, обучите финальные базовые модели на всех разрешённых обучающих строках,
а финальную мета-модель — на OOF-оценках. В текущем ноутбуке это уже делает
`SAVE_STACKING_FINAL=True`.

Скопируйте содержимое `notebook_export_cell.py` целиком в новую последнюю ячейку
после сохранения `inference.py`, `stacking_features.py`, `stacking_inference.py` и моделей.
Она использует переменную `RESULTS` и формирует `classification_model.zip`.
Распакуйте содержимое этого ZIP прямо в `models/classification/`, без дополнительной
вложенной папки. Обновляйте файлы экспорта вместе и перезапускайте сервис.

Альтернатива — экспортировать обычный ZIP результатов уже на компьютере:

```bash
python tools/export_classifier.py metadata_results_НОВЫЙ_ЗАПУСК.zip --output models/classification
```

Для исходного контрольного CatBoost добавьте `--kind catboost`.
При смене среды возьмите версии из нового `requirements_versions.txt`.
Для надёжного повторения будущих запусков фиксируйте также конкретный commit
`RUBERT_REVISION` вместо изменяемого `main` до расчёта эмбеддингов и обучения.

В сервис переносится финальный bundle вместе с кодом предобработки и признаков.
Таблицы OOF, ошибки CV, обучающий Excel и `rubert_cache/*.npy` не нужны для новых обращений.
При запросе выполняются только transform/predict; fit, обучение, подбор параметров
и выполнение ноутбука остаются вне сервиса.

**8. Проверка перед демонстрацией.**

Проверьте одинаковое обращение в ноутбуке и сервисе с одинаковыми метаданными:
порядок классов, категория и топ-3 должны совпасть с учётом небольших численных различий
между CPU/GPU. Также проверьте пустое описание, пропущенный компонент и неверный
исходный вид запроса. Замена исходного вида не должна менять прогноз модели.

Комплект не содержит HTTP-сервера: текущий фронтенд Streamlit вызывает Python-сервис
на сервере напрямую. Если позже появится отдельный React/Vue-фронтенд, этот же `predict`
можно обернуть HTTP-методом. Загружать joblib в браузер не требуется.

Веса в `models/classification/` исключены из Git вложенным `.gitignore`.
Загружайте собственный доверенный экспорт; joblib — формат Python-сериализации.

Результаты проверки комплекта и версии проверочной среды описаны в `VALIDATION.md`.

Документация: [кеш ресурсов Streamlit](https://docs.streamlit.io/develop/api-reference/caching-and-state/st.cache_resource),
[сохранение моделей scikit-learn 1.6](https://scikit-learn.org/1.6/model_persistence.html).
